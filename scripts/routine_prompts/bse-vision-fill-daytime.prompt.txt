EXTRACTION RULES (copy verbatim into every subagent prompt):
   For EACH company, Read each of its PNG paths (this is VISION — OCR doesn't work on these scanned filings). Each company comes with `qe` and `quarters` = {cur, prev, yago}: the quarter-end dates of the three columns to read. From the Profit & Loss statement extract, in RUPEES CRORE, for THREE quarters when the columns are present — the quarter ended quarters.cur (the current quarter), the quarter ended quarters.prev (the "previous quarter" column), and the quarter ended quarters.yago (the year-ago column):
   - rev = Revenue from Operations (for banks/NBFCs use "Total Income"; if only "Total Income"/"Total Revenue" is shown, use that)
   - op = Operating Profit / EBITDA — ONLY if the statement prints such a line (e.g. "Operating Profit", "EBITDA", "Profit from operations"). If there is no explicit operating-profit line, set op to null. Do NOT compute or guess it.
   - pat = Profit After Tax / "Profit for the period" (owners' share if consolidated)
   Mind the unit note printed on the statement: "in Lakhs"/"in Lacs" ÷100; "in Millions" ÷10; "in Thousands" ÷10000; absolute rupees ÷10000000; "in Crores" keep as-is. The unit varies per statement — read the note every time, never assume crore. (1 crore = 10,000,000 rupees, so a thousands figure ÷10000. This line read ÷100000 until 2026-07-17 — 10x wrong, which silently understated every thousands-denominated filing; GYANDEV Q1FY27 PAT came out -0.0041 cr instead of -0.057 cr.)
   CROSS-CHECK THE UNIT whenever the statement prints EPS and paid-up capital: PAT ÷ (paid-up capital ÷ face value) must equal the printed EPS. GYANDEV: 30,000 thousand capital ÷ ₹10 = 3,000,000 shares; -0.057 cr ÷ 3,000,000 = -0.19 = the printed EPS ✓. If your figure fails this by a power of ten, your unit divisor is wrong — fix it, don't report the number.
   COLUMN ORDER IS NOT UNIFORM. Some filings print current / previous / year-ago, others print current / year-ago / previous (year-ago BEFORE previous-quarter), and some carry extra year-to-date or full-year columns whose end date can equal a quarter's. ALWAYS map each column by reading its printed header date and "3 months / quarter ended" heading, NEVER by position. If the statement's own current quarter is NOT quarters.cur (the filing is for a different quarter), set ok:false and say so in "note" — never re-date a column to fit.
   Prefer CONSOLIDATED if both consolidated and standalone are shown — but only if the consolidated P&L TABLE is actually present; an attachment sometimes carries the consolidated auditor's report WITHOUT the consolidated numbers, in which case use standalone and set basis "S". A quarter column that isn't present → null that quarter's figures. Verify the company name in the image matches the one given — if it's a different company or the P&L isn't present, mark ok:false.
   Output a JSON array, one object per company, carrying through exch, sym, scrip and qe exactly as given:
   [{"exch":"BSE","sym":"BENARAS","scrip":"509438","qe":"20260930","ok":true,"basis":"S","cur":{"rev":35.2,"op":null,"pat":8.2},"prev":{"rev":30.0,"op":null,"pat":6.0},"yago":{"rev":26.8,"op":null,"pat":7.6}}, ...]
   (cur = the quarters.cur column, prev = quarters.prev, yago = quarters.yago. The numbers above only illustrate the shape.)
   basis is "C" for consolidated, "S" for standalone. Use null for any single figure you can't read; ok:false (with null figures) if you couldn't read the company. NEVER invent a number.
